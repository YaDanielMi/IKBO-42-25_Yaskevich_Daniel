# Shell Emulator

Эмулятор командной оболочки UNIX-подобной ОС с графическим интерфейсом.
Написан на Python 3 с использованием tkinter, внешних зависимостей нет.

Эмулятор принимает команды в окне, похожем на терминал, и выполняет их
над виртуальной файловой системой (VFS), которая целиком загружается в
память из обычного каталога на диске.

- [x] Этап 1. REPL: GUI, парсер с кавычками, команды-заглушки, `exit`
- [x] Этап 2. Конфигурация: параметры запуска, стартовые скрипты
- [x] Этап 3. VFS: файловая система в памяти, реальные `ls` и `cd`

## Функции

### Окно и диалог

- Заголовок окна `Эмулятор - [username@hostname]`: имя пользователя и
  хоста берутся из реальной ОС.
- Приглашение `user@host:/путь$`, история команд на стрелках вверх/вниз,
  ошибки выделены цветом.

### Разбор командной строки

- Одинарные и двойные кавычки (`ls "my dir"`), экранирование (`my\ dir`),
  пустой аргумент `""`.
- Комментарий начинается с `#` в начале слова вне кавычек
  (`ls a#b` — это аргумент `a#b`).
- Ошибки: незакрытая кавычка, обрыв после `\`, неизвестная команда.

### Команды

- `ls [-a] [-l] [путь...]` — список каталога.
  - `-a` — показать скрытые файлы, `.` и `..`;
  - `-l` — подробный формат: тип (`d` или `-`), размер, имя;
  - ключи можно склеивать (`-la`), `--` заканчивает список ключей;
  - файлы выводятся первым блоком, каталоги — с заголовком `путь:`,
    если аргументов несколько.
- `cd [путь]` — сменить каталог.
  - без аргумента — переход в корень;
  - `cd -` — в предыдущий каталог (путь выводится);
  - `..` выше корня остаётся в корне.
- `exit [код]` — завершить работу, код возврата берётся по модулю 256.
  Нечисловой код — ошибка и выход с кодом 2, как в bash.

Если VFS не подключена (нет `--vfs`), `ls` и `cd` работают как заглушки и
печатают своё имя и аргументы.

Ошибки в стиле bash, например:
`cd: missing: Нет такого файла или каталога`, `cd: file.txt: Не каталог`,
`ls: неверный ключ -- 'z'`. Ошибки команд не прерывают стартовый скрипт.

### VFS

- Источник — каталог на диске, он один раз читается целиком в память
  (структура и содержимое файлов). Все операции работают только с этой
  структурой, диск не изменяется и больше не читается. Каталог можно
  удалить во время сеанса, эмулятор продолжит работу.
- Символические ссылки и специальные файлы пропускаются.
- VFS доступна только для чтения.

## Настройки (параметры командной строки)

| Параметр | Описание |
|----------|----------|
| `--vfs PATH` | каталог на диске — физическое расположение VFS |
| `--script PATH` | стартовый скрипт с командами эмулятора |
| `--headless` | консольный режим без окна (для автоматизации и скриптов ОС) |

При запуске все параметры (и абсолютные пути) выводятся отладочными
строками `[debug]` в терминал, а в GUI-режиме и в окно. Неверные значения
дают сообщение `Ошибка: ...` и код возврата 1.

### Стартовый скрипт

Текстовый файл UTF-8, одна команда на строку (примеры: `examples/startup`).

- `# ...` — комментарий; строка показывается в диалоге, но ничего не
  делает, как в настоящей оболочке; пустые строки пропускаются;
- при выполнении на экране виден и ввод (`user@host:/$ команда`), и вывод;
- `exit [код]` завершает скрипт; если его нет, эмулятор остаётся в
  интерактивном режиме (в окне; в `--headless` читает stdin до `exit`
  или конца ввода, вводимые из канала строки выводятся как диалог);
- если скрипт закончился `exit`, окно остаётся открытым только для
  чтения, чтобы можно было посмотреть результат.

## Сборка и тесты

Сборка не требуется. Нужны Python 3.8+ и tkinter
(Debian/Ubuntu: `sudo apt install python3-tk`; без него работает
`--headless`).

```sh
make test      # unit-тесты (unittest, 99 тестов)
make lint      # flake8 (pip install flake8)
make demo      # все демонстрационные скрипты ОС подряд
```

## Запуск

```sh
./run.sh                                        # окно, VFS нет
./run.sh --vfs examples/vfs/deep                # окно с VFS
./run.sh --vfs examples/vfs/deep \
         --script examples/startup/all_commands.emu
./run.sh --headless --vfs examples/vfs/several  # консоль, команды со stdin
```

### Скрипты ОС (`scripts/`)

| Скрипт | Что проверяет |
|--------|---------------|
| `stage2_params.sh` | все параметры с корректными значениями |
| `stage2_errors.sh` | неверные значения, пропущенное значение, неизвестный ключ |
| `stage2_script_features.sh` | комментарии, ошибки в скрипте, `exit`, переход на stdin |
| `stage3_vfs_variants.sh` | VFS: минимальный, пустой, несколько файлов, 4 уровня |
| `stage3_vfs_errors.sh` | ошибки загрузки VFS и ошибки команд |
| `stage3_in_memory.sh` | каталог удаляется во время сеанса; файлы на диске не меняются |
| `stage3_all_commands.sh` | стартовый скрипт со всеми командами и режимами |

### Примеры VFS (`examples/vfs/`)

- `minimal` — один файл;
- `several` — несколько файлов в одном каталоге (есть скрытый и
  файл с кириллическим именем);
- `deep` — 4 уровня вложенности (`/docs/guides/advanced/tuning.txt`),
  каталог с пробелом в имени, скрытый каталог, «пустой» каталог.

## Пример сеанса

```text
$ ./run.sh --headless --vfs examples/vfs/deep
```

## Структура

```text
src/                исходный код
  main.py           точка входа, параметры, запуск
  config.py         параметры командной строки, отладочный вывод
  cmdparser.py      разбор строки с кавычками
  shell.py          интерпретатор и состояние оболочки
  commands.py       команды ls, cd, exit
  vfs.py            VFS в памяти и загрузка с диска
  vfs_commands.py   ls и cd поверх VFS
  script.py         чтение и воспроизведение стартовых скриптов
  gui.py            окно tkinter
  console.py        консольный режим (--headless)
tests/              unit-тесты
scripts/            скрипты ОС (sh), вызывающие эмулятор
examples/startup/   стартовые скрипты эмулятора (*.emu)
examples/vfs/       примеры каталогов для VFS
run.sh, Makefile    запуск, тесты, линтер, демо
```
